# תכנון גיבוי ושחזור Google Drive

## החלטות מוצר

- החיבור אופציונלי והאפליקציה ממשיכה לעבוד מול Supabase גם ללא Drive.
- לכל משתמש ניתן לחבר חשבון Google אחד בכל רגע נתון.
- האפליקציה יוצרת תיקייה גלויה בשם `גיבויי המשימות שלי` וקובצי JSON קריאים.
- נשמרים 5 גיבויים שעתיים ו-5 גיבויים יומיים. הגיבוי היומי נוצר סביב 03:00 לפי אזור הזמן של המשתמש.
- חמשת הגיבויים הידניים וחמשת גיבויי `pre-restore` האחרונים נשמרים בנפרד.
- בניתוק נמחק אסימון הגישה השמור, אך קובצי Drive נשארים. מחיקתם היא פעולה נפרדת עם אישור.
- בהתחברות הראשונה מוצע חיבור Drive. לאחר `לא עכשיו` מוצעת תזכורת אחת נוספת אחרי 30 יום.

## אבטחה ופרטיות

- נעשה שימוש ב-OAuth Web Server וב-scope המצומצם `drive.file`.
- refresh token נשמר מוצפן ב-AES-256-GCM בטבלה פרטית ללא מדיניות גישה ללקוח.
- כל מסלולי המשתמש מאמתים Supabase Bearer token. מסלול cron מאמת סוד ייעודי.
- הגיבוי כולל רק משימות בבעלות המשתמש, taxonomy והגדרות. שיתופים מצורפים כתיעוד בלבד.
- שחזור אינו משנה רשומות שיתוף ואינו מוחק משימות חדשות; משימות שאינן בגיבוי מסומנות כמבוטלות כדי לשמור היסטוריה ומזהים.
- לפני שחזור נוצר גיבוי `pre-restore`, והפעולה דורשת Preview ואישור מפורש.

## תשתית ותזמון

- Supabase Cron מפעיל אחת לשעה endpoint מאובטח ב-Vercel.
- הריצה יוצרת גיבוי שעתי, ובשעה המקומית 03:00 גם גיבוי יומי אם טרם נוצר באותו יום.
- כשל של משתמש אחד אינו מפיל את גיבויי שאר המשתמשים.
- נשמרים זמן ניסיון אחרון, זמן הצלחה אחרון ושגיאה אחרונה להצגה בממשק.

## שלבי ביצוע

1. OAuth, טבלאות פרטיות, תיקיית Drive וגיבוי ידני.
2. cron שעתי, גיבוי יומי ומדיניות 5+5.
3. רשימת גיבויים, Preview, checksum ושחזור בטוח.
4. onboarding, ניתוק, טיפול בכשלים ו-QA.
