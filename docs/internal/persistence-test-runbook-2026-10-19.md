התחליף ל־Supabase ב־`fixtures.mjs` אינו בודק RLS, נעילות, רשת אמיתית או מספר חיבורים. הוא מפעיל קוד TypeScript אמיתי מול transport בזיכרון עם סדר כתיבות ידוע. בדיקות SQL משלימות אותו באילוצי PostgreSQL אמיתיים, אך PGlite חד־תהליכי אינו מוכיח התנהגות של שרת Supabase מרובה חיבורים. ה־schema המקומי אינו שחזור מלא של כל המיגרציות או של Production.

רכיב הדף ונתוני ההתחלה האישיים אינם מורצים. פונקציות מספור ונרמול נשלפות דרך AST לפי שם; שינוי מיקומן יכשיל את מתאם הבדיקה במפורש, לא יפעיל fallback. אין טעינת `.env`, מפתחות, קובץ הגיבוי או לקוח Supabase אמיתי. כל הרשומות, המשתמשים, המיילים והטקסטים המשמשים לבדיקות סינתטיים. אין פנייה לספק AI, Drive או שירות בתשלום.

## 2. הרצה חוזרת

מ־root של המאגר, לאחר התקנת תלויות הפרויקט:

```powershell
$env:PGLITE_MODULE_PATH = '<absolute path to @electric-sql/pglite/dist/index.js>'
npm run test:persistence
npm run test:persistence:gate
```

נבדק עם PGlite `0.5.8`, בהתקנה המקומית המבודדת שכבר קיימת לצורכי התאוששות. לא נוספה תלות Production או תלות למסד באפליקציה. ניתן להכין מחדש runtime בדיקות מחוץ למאגר באמצעות התקנת `@electric-sql/pglite@0.5.8` בספריית בדיקה ייעודית; אין להריץ התקנה על נתוני משתמש ואין לטעון כתובת מסד חי.

הפקודה הראשונה היא **שחזור סיכונים + בדיקות בסיס + מלאי בדיקות עתידיות**, לא אישור מוכנות לפריסה. ללא `PGLITE_MODULE_PATH` שכבת SQL מסומנת SKIP באופן מפורש. פקודת gate דורשת אותו ומחזירה קוד יציאה שאינו אפס כשחסר מימוש יעד. אין להחריג את כישלון ה־gate ב־CI כדי להציג את הפרויקט כמוכן למעבר.

לבדיקות יעד, חבילה 6 תספק מודול מקומי ותגדיר:

```powershell
$env:PERSISTENCE_TEST_ADAPTER = '<absolute path to the real synthetic implementation adapter.mjs>'
npm run test:persistence:gate
```

אין כיום מתאם כזה. לא נכתב מנוע ״פתרון״ בתוך הבדיקות כדי לגרום להן לעבור. אין להצביע על מתאם Production או לעקוף TODO באמצעות החזרת תשובות קבועות. יש לקרוא בנפרד את pass/fail/skip/todo: Node עשוי לצייר סימן חיובי לצד TODO, אבל הוא **אינו בדיקה שעברה**. בדיקת מלאי בודקת IDs מסודרים וייחודיים וקישור למסמכי התכנון; אינה מאמתת את assertions מול מימוש שטרם נכתב.

## 3. חוזה מתאם הבדיקה לחבילה 6

זהו port פנימי לבדיקות, לא החלטה על HTTP/RPC ציבורי ולא API חדש למוצר. כל תרחיש מתחיל ב־fixture חדש משלו ונסגר ב־finally. `syntheticSeed` ו־`command()` בקובץ `scripts/persistence/contract-cases.mjs` הם מקור הצורות המדויק.

- המודול מייצא `capabilities` עם `syntheticOnly: true`, `productionTarget: false`, `realImplementation: true`; שער השחרור דורש גם `renderedUi: true`. אלה הצהרות מתאם שחייבות ביקורת קוד, לא מנגנון אבטחה נגד מתאם זדוני.
- `createHarness(seed)` מקים סביבה מבודדת למימוש האמיתי. אין חיבור לפי משתני Production. `close()` משחרר אותה גם כשהבדיקה נכשלת.
- `send(actor, command)` מפעיל את נתיב הפקודה האמיתי תחת auth סינתטי. תוצאות משתמשות בסטטוסים מחוזה חבילה 3. `read(actor, uuid)` מחזיר רק snapshot מורשה, עם revision/writeEpoch כמחרוזות. השמות בגבול הבדיקה ממופים בידי המתאם לשמות הסכמה האמיתיים.
- `race([{actor, command}, ...])` מתחיל בקשות חופפות במחסום דטרמיניסטי, לא לולאת await סדרתית. אימות נעילות מלא דורש גם סביבת PostgreSQL מבודדת מרובת חיבורים בחבילות 6–7; לא לטעון ש־Promise.all בלבד מוכיח זאת.
- `inspect()` קורא את המשימות, counters, writeEpoch, receipts ו־proposalExecutions מתוך המסד המבודד, לא ממערך תגובות. ההיטל דטרמיניסטי, מסודר, ללא שדות זמן נדיפים; snapshots להשוואת rollback כוללים כל מצב עסקי ובקרת כתיבה.
- `fixture(name, payload)` מכין הרשאה/הקצאה, הצעת AI סינתטית, הסרת המספר הגבוה, גרסת taxonomy או שחזור ישן. זו הכנת בדיקה בלבד. שינוי הרשאה/שחזור המיועדים להיבדק חייבים לעבור בנתיב המימוש האמיתי; אין לשנות ישירות שורה במקום לבחון את הטרנזקציה שלה. ה־fixture של מחיקה משמר high-water ומסיר את משימה P2 והצעד 1 של P1; T11 דורש מספרים חדשים מעליהם.
- `fault(point, reason)` מזריק תקלה חד־פעמית בגבול האמיתי: before_commit/after_commit/import_after_first_write. timeout לפני COMMIT מבטל את הטרנזקציה; אחריו מאבד רק את התשובה. receipt_insert_failure/deadlock מחזירים `SYNTHETIC_TRANSACTION_ABORT`; constraint_failure מחזיר `SYNTHETIC_CONSTRAINT_FAILURE`. אסור להחליף את טרנזקציית היישום במנוע דמה שמיישם את ההתנהגות הרצויה.
- `receipt(actor, operationId)`, `legacyWrite(actor, route, patch)` ו־`page(actor, options)` פונים למסלולי הקבלה, DML/RPC הישנים והקריאה האמיתיים בסביבה המבודדת. נתיב legacy אמיתי שחסר לאחר ההחלפה נחשב חסום; אין להחזיר ״denied״ מהמתאם בלי ניסיון או ראיה למסלול שהוסר.
- `client()` מחזיר את state machine/הממשק האמיתי תחת transport ואחסון סינתטיים. `event(name, payload)` מזריק כוונת משתמש, אירוע דפדפן או תשובת רשת. `view()` קורא את המצב הנצפה. שמות האירועים והשדות מפורטים ב־`ui-cases.mjs` וב־T12–T14/T21. אין לעדכן state בדיקה במקום להפעיל קוד מוצר.
- `measure()` ב־U16 קורא מממשק מרונדר רוחב גלילה, גודל יעדי מגע, כיוון, פוקוס, נעילת רקע ונראות פקד לאחר שינוי viewport. נדרשת בנוסף בדיקה ידנית במובייל אמיתי למקלדת/קורא מסך; מדידת viewport אינה הוכחה להתנהגות מקלדת פיזית.

בהחלפת המימוש, R/S המתעדים פגיעות צפויים להפסיק לשחזר אותה. אין לשנות את assertions שלהם כדי להסתיר כשל: מחליפים או פורשים כל שחזור רק עם קישור לבדיקה ירוקה מול המימוש החדש של אותו סיכון. B נשארים בדיקות רגרסיה. ה־gate הנוכחי כולל גם את ה־baseline הישן, ולכן חבילה 6 תעדכן במפורש את המלאי בעת הסרת הכותב הישן.

## 4. ממצאים ותוצאת הריצה

בריצה המקומית ב־19.10.2026 נבדקו: R01–R09, B01–B05, S01–S06 ומלאי התרחישים. אלה 20 בדיקות התנהגות ובדיקת מלאי אחת; Node סופר גם את מעטפת SQL, ולכן הסיכום הצפוי הוא 22 pass. 40 בדיקות היעד מסומנות TODO; בדיקת gate מסומנת SKIP בהרצה הרגילה בלבד. אין להסיק מ־exit 0 של הרצה זו שהמנגנון העתידי מוכן.

הסיכונים ששוחזרו: דריסה באותו שדה ובשדות שונים, דריסת משימה אחרת מרשימה ישנה, איחוד שתי יצירות עקב מספר זהה, מחזור מספר אחרי הסרה, ACK אבוד אחרי כתיבה, אובדן צעד שהושלם, השמטת צעדים ב־fallback, קריאה חלקית לא מסומנת, DML ישיר ושינוי מספר ברמת הסכמה הקיימת. R04 ו־S05 בוחנים אותו סיכון בשתי שכבות משלימות, לא שני אירועי אובדן נפרדים.

נמצאו גם הגנות קיימות: סינון לקוח למשימות שאינן שלו, נרמול P/W, שימור מספור עבור היסטוריה שעדיין במערך, קריאה עצמאית ללא כתיבה, RLS בסיסי, unique עבור INSERT רגיל ו־rollback אחרי כשל אילוץ. אין בכך אימות לכל callbacks בדף, כל RPC שיתוף או כל ההרשאות החיות; בדיקת SEC01 הייעודית נפרדת.

שער השחרור אמור להיכשל כעת בקוד 1 בגלל חסרון מתאם המימוש; זו תוצאת בטיחות צפויה, לא תקלה שסומנה כבדיקה שעברה. השלמת חבילה 5 משמעה תשתית ובדיקות כתובות + ראיות לסיכונים הקיימים, **לא** סגירת 40 תרחישי הקבלה ולא הרשאה למיגרציה חיה.

אימות בפועל בענף הפרסום הנקי: `npm run test:persistence` החזיר 22 pass, אפס fail, 40 TODO ו־SKIP אחד לבדיקת gate שאינה מופעלת במצב רגיל. `npm run test:persistence:gate` נבדק עם מסלול PGlite והחזיר 1 כמצופה בגלל מתאם חסר. `npm run lint` עבר. `npm run build` המקומי נחסם במגבלת Turbopack על קישור node_modules מחוץ לשורש ה־worktree; `npm run build -- --webpack` עבר כולל TypeScript ויצירת כל הדפים. לא שונתה תצורת הבנייה. diff מול בסיס הפרסום אישר שאין שינוי ב־src, ב־supabase או ב־package-lock.json. אין זרימת UI חדשה לבדיקת דפדפן בחבילה זו; בדיקות UX האמיתיות עדיין חסומות ומסומנות כך.
