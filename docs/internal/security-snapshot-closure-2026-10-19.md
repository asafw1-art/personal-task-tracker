# SEC01: סגירת גישה חיצונית לפונקציית תצלום שיתוף

תאריך: 19.10.2026. סטטוס: תוקן ואומת ב־Production באישור אסף. אין שינוי בתוכן משימות.

## השינוי

`supabase/harden-task-share-snapshot-access.sql` שולל את הרשאות הפעלת `public.task_share_snapshot(uuid)` מ־PUBLIC, anon ו־authenticated. שלילה מ־PUBLIC לבדה לא הספיקה בגלל ההרשאות האפקטיביות שנמצאו בחי. המיגרציה טרנזקציונית, חוזרת ובודקת שההרשאה אכן נחסמה. אין שינוי בגוף הפונקציה, בבעלותה, בנתונים או במסלולי revoke/leave המורשים.

## בדיקות וקבלה

- `scripts/test-sharing-snapshot-access.mjs` רץ ב־PGlite מקומי בלבד, עם משתמשים ומשימות סינתטיים.
- שוחזרה החשיפה לפני התיקון על נתוני בדיקה; אחרי שתי הרצות מיגרציה, anon, משתמש זר וגם בעל המשימה אינם יכולים לקרוא ישירות ל־helper.
- ביטול שיתוף בידי בעלים ועזיבה בידי נמען פועלים ושומרים snapshot עם הערות וצעדים; טריגרי סיום ההקצאות פועלים. משתמש זר נדחה.
- גוף הפונקציה ונתוני המשימות הסינתטיים לא הוחלפו. גישת service_role הקיימת נשמרה ולא הורחבה.
- lint ו־build עברו.
- commit מקומי: `380cf83`; commit release: `4c32d2d`. הועלה דרך worktree נקי בלבד. בדיקת Vercel החזירה success: https://vercel.com/weizman1/personal-task-tracker/EbSt4F3Hkh9LUXogrz2QV6bMN45F .

## אימות חי

המיגרציה הורצה ב־SQL Editor בפרויקט הקיים. SELECT לפני/אחרי הראה:

| בדיקה | לפני | אחרי |
|---|---|---|
| anon EXECUTE | true | false |
| authenticated EXECUTE | true | false |
| service_role EXECUTE | true | true |
| בעלים | postgres | postgres |
| MD5 של גוף הפונקציה | d3af443d5a5e7a55c47e8bd5f96b88af | זהה |

MD5 כאן הוא אות השוואה תפעולי לגוף הפונקציה, לא חתימת אבטחה לגיבוי. אין בבדיקה טענה שלא התרחש ניצול בעבר. לא נקראה משימה אמיתית דרך הפונקציה, ולא בוטל שיתוף אמיתי לצורך QA. בדיקת ההתנהגות נעשתה בסביבה סינתטית; בחי אומתו ההרשאות ושימור הגוף.

צילום אימות פרטי, מחוץ ל־Git: תיקיית `recovery-2026-10-19` בשורש הארטיפקטים המקומי, קובץ `snapshot-access-fixed.png`.

## תפעול ונסיגה

אין להחזיר EXECUTE ללקוחות כדרך נסיגה. במקרה של תקלה בשיתוף, בודקים את ה־RPC המורשה ואת זהות בעל הפונקציה בסביבה מבודדת; אין לפתוח מחדש את ה־helper. החזרת גרסת frontend ישנה אינה צריכה לשנות את ההרשאות הללו. לא שונו הגדרות AI/Gateway, Google OAuth, חיוב או נתוני יישום.

בהתקנה חדשה יש להריץ את מיגרציית ההקשחה אחרי מיגרציות השיתוף ולבדוק את ההרשאה האפקטיבית, לא רק את נוסח REVOKE PUBLIC בקובץ ישן.
